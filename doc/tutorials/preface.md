# 序言：智能体的第一推动力 —— 从黑盒调用到白盒物理沙箱

我们正在经历一场前所未有的范式变革。

在过去的几年里，大语言模型（LLM）的爆发让整个行业陷入了对“提示词魔法”的狂热。人们惊叹于只要在聊天输入框里敲入几行自然语言，AI 就能写出通顺的文案、甚至跑出能运行的简易程序。然而，狂热退去之后，开发者们很快撞上了玻璃天花板：
*   为什么我的聊天机器人聊着聊着就会“遗忘”上文？
*   为什么让它调用一个简单的天气 API，它却经常传错参数？
*   为什么在处理复杂的长链路任务时，它会陷入反复确认的“鬼打墙”状态？

这些问题的答案，隐藏在“文字接龙聊天助手”与“能动的智能体（Agent）”之间的鸿沟里。

市面上绝大多数教程会教你如何安装 LangChain、LlamaIndex 或是使用 AutoGPT 等黑盒框架。它们通过层层叠叠的类（Classes）和复杂的对象抽象，把大模型的 Raw HTTP 调用和心智决策死循环封装在厚厚的冰山之下。初学者往往只需要敲入两行代码 `agent.run("do something")` 就能跑起一个 Demo。然而，一旦程序在生产环境中崩溃，面对成百上千行的报错栈，没人知道那座冰山下面到底发生了什么。

**这正是我们编写这本书的初衷：拆掉冰山，还你物理世界。**

本书不依赖任何第三方臃肿的 Agent 框架。我们将大模型的底层文字接龙机制、JSON Schema 的参数推导控制流、OpenAI 与 Gemini 的 Function Calling 网络原始数据包，乃至流式传输的 SSE Delta 协议，像解剖生物标本一样，毫无保留地摊在你的面前。

为了让你能够看清这些底层原理在代码中的物理投射，我们为你提供了一个完全透明、极致精炼的开源白盒沙箱 —— **Freya**。

在接下来的 13 个章节中，Freya 将成为你的白盒透视镜。你将跟着我们，一步步读懂 `agent-executor.ts` 中的 `while(loop)` 决策死循环，看清 `SessionCompactor` 如何在 Token 溢出时调用 LLM 剔除冗余，以及 Abort 信号如何在多层异步流中层层传递、强行“刹车”。

这不是一本教你如何“调包”的手册，而是一部教你如何从零制造一台智能体引擎的“手艺人指南”。

欢迎来到智能体的物理世界。让我们开始。
