# 3.3 【白盒剖析】双通道动态提示词合并

在 3.2 节中，我们建立了将提示词模板以下沉的 Markdown 文件形式存储在磁盘上的物理规范。然而，在智能体的实际部署中，我们面临着多环境覆盖的诉求：我们希望系统内置一套“开箱即用”的默认提示词；同时，又希望用户能在不修改只读源码包的前提下，在运行时通过在特定目录放置自定义文件来覆盖这些提示词。

本节我们将实际解剖 Freya 底座中负责这一生命周期管理的核心模块 —— **提示词注册表**（位于 `packages/core/src/prompt/prompt-registry.ts`）。

我们将一起看懂它是如何通过**双通道探针机制（Dual-Read）**进行文件的加载避让，以及如何将时间时区、工具附加指示和插件技能卡动态合成为一个单体系统提示词的。

---

## 一、 双通道探针机制 (Dual-Read) 的物理实现

为了实现“内置只读，外置覆盖”的优雅架构，`FreyaPromptRegistry` 中定义了 `register()` 方法。

在注册每一个提示词时，它都会启动两个物理探针去触碰磁盘文件：

```typescript
export interface FreyaPrompt {
  key: string;
  content: string;
  defaultPath: string; // 包内默认路径 (只读)
  runPath?: string;    // 用户运行时覆盖路径 (可写)
}

export class FreyaPromptRegistry {
  private prompts = new Map<string, FreyaPrompt>();

  /**
   * 注册提示词元数据声明并执行异步双读载入
   */
  async register(prompt: Omit<FreyaPrompt, 'content'>): Promise<void> {
    const runFilePath = this.getRunFilePath(prompt);
    let content = '';

    try {
      try {
        // 通道 1：探针尝试读取用户运行目录下的覆盖配置 (config/ 目录)
        content = await fs.readFile(runFilePath, 'utf-8');
      } catch {
        // 通道 2：若通道 1 抛出文件不存在异常，降级加载只读的程序包默认配置
        content = await fs.readFile(prompt.defaultPath, 'utf-8');
      }
    } catch {}

    this.prompts.set(prompt.key, {
      key: prompt.key,
      content: content.trim(),
      defaultPath: prompt.defaultPath,
      runPath: prompt.runPath
    });
  }
}
```

### 物理设计优势：
这种双读探针（Dual-Read）的设计在生产部署中极为强大：
1.  **物理防呆与降级**：即使管理员在运行时把外置的配置文件误删了，底座也不会挂起报错，而是会自动回退加载只读包内的默认模板。
2.  **安全隔离**：核心程序包（`APP_ROOT`）可以被设置为只读挂载（在 Docker 容器等环境中），而所有用户配置（`PROJECT_ROOT`）写在隔离的宿主持久化目录中。

## 二、 基础系统提示词的内存编织

当所有的系统核心提示词（`identity` 身份, `soul` 灵魂, `tools` 工具, `agents` 拓扑, `user` 用户画像, `memory` 长期记忆）通过双通道加载进 Map 后，`getSystemPrompt()` 会负责它们的第一层拼接。

在此过程中，它展示了底座如何向大模型动态注入**“真实时间与时区”**：

```typescript
getSystemPrompt(): string {
  const identity = this.get('core.prompt.identity');
  const soul = this.get('core.prompt.soul');
  const user = this.get('core.prompt.user');
  const memory = this.get('core.prompt.memory');
  const tools = this.get('core.prompt.tools');
  const agents = this.get('core.prompt.agents');

  // 1. 动态抓取当前操作系统的本地时区
  const timeZone = Intl.DateTimeFormat().resolvedOptions().timeZone || 'Asia/Shanghai';
  const now = new Date();
  const nowStr = now.toLocaleString('zh-CN', { timeZone });
  const weekday = ['日', '一', '二', '三', '四', '五', '六'][now.getDay()];

  // 2. 计算时区偏差偏移量 (如 +8)
  const offsetMinutes = -now.getTimezoneOffset();
  const sign = offsetMinutes >= 0 ? '+' : '-';
  const absHours = Math.floor(Math.abs(offsetMinutes) / 60);
  const absMins = Math.abs(offsetMinutes) % 60;
  const utcOffset = `UTC${sign}${absHours}${absMins > 0 ? `:${absMins.toString().padStart(2, '0')}` : ''}`;

  const timeStr = `${nowStr} (星期${weekday}, 时区: ${timeZone}, ${utcOffset})`;

  // 3. 多维度标准 Markdown 拼接
  return `# IDENTITY (本体)\n${identity}\n\n` +
    `# SOUL (灵魂)\n${soul}\n\n` +
    `# USER INFO (用户画像)\n${user}\n\n` +
    `# MEMORY (长期记忆)\n${memory}\n\n` +
    `# TOOLS SPEC (工具指南)\n${tools}\n\n` +
    `# AGENT TOPOLOGY (拓扑模式)\n${agents}\n\n` +
    `# CURRENT TIME (当前时间)\n${timeStr}`;
}
```

自回归大模型无法感知物理世界的时间流逝。如果不在 System Prompt 头部注入当前时间，当用户问“我昨天发的那封警告信，今天到期了吗？”，大模型会因为缺乏时间基准给出错误的接龙概率。Freya 通过同步抓取操作系统时区偏移量，在物理层面上补全了大模型的心智拼图。

## 三、 动态插值：composeSystemPrompt() 运行时组装

在 2.3 节我们读到，在每一次 `while(loop)` 决策环的开头，都会执行 `composeSystemPrompt()`。

它是最终系统提示词出厂的合成车间。它会根据当前智能体正在执行的技能卡、可用的备用技能卡以及激活的工具列表，将附加信息“热拼接”到 System Prompt 的最尾部：

```typescript
composeSystemPrompt(
  activeSkill?: { id: string; content: string },
  toolInstructions: string[] = [],
  availableSkills: { id: string; name: string; description?: string }[] = []
): string {
  // 1. 获取包含时间戳的基础 System Prompt
  let systemPrompt = this.getSystemPrompt();

  // 2. 如果存在激活的工具的附加特殊说明，追加拼接入内
  if (toolInstructions.length > 0) {
    systemPrompt += `\n\n# TOOLS ADDITIONAL INSTRUCTIONS\n${toolInstructions.join('\n\n')}`;
  }

  // 3. 动态展示当前系统安装的所有可用技能卡 (并引导 LLM 具有调用 activate_skill 的概念)
  if (availableSkills && availableSkills.length > 0) {
    const listLines = availableSkills
      .map((s) => `- **${s.name}** (技能ID: \`${s.id}\`)\n  ${s.description || '无描述'}`)
      .join('\n');
    systemPrompt += `\n\n# AVAILABLE SKILLS (可用技能卡列表)\n本系统当前已物理安装并扫描到如下可用特长技能卡（你可通过调用 \`activate_skill("技能ID")\` 激活对应模式）：\n\n${listLines}`;
  }

  // 4. 将当前 Session 正在处于活跃期的特定技能卡（插件）Prompt 合并入内
  if (activeSkill && activeSkill.content) {
    systemPrompt += `\n\n# PLUGIN PROMPT [${activeSkill.id}]\n${activeSkill.content}`;
  }

  return systemPrompt;
}
```

通过这一层拼接，大模型在每次 ReAct 推理时，其上下文的最后几行总是能接收到最新、最精准的技能和工具边界声明，从而指引其进行最理性的 Tool Call 参数预测。
