# 11.3 动手实验：反射循环开发

在 11.2 节中，我们从理论和架构高度解析了 Reflexion 反思模型的设计哲学与三原色角色分工。本节我们将通过一个**硬核的本地动手实验**，亲自用 JavaScript/TypeScript 编写一个具备“自我审查（Critic）”与“反思修复（Self-Correction）”闭环的代码自动改错智能体。

我们将设计一个极易让普通大模型写出 Bug 的“边界条件代码编写任务”，并让智能体在单元测试裁判的无情打击下，通过自我反思，在第二轮中瞬间修正 Bug。

此外，我们还将针对动态评估代码时极易触发的**本地远程代码执行（RCE）安全漏洞**提供虚拟机沙箱防护方案。

---

## 一、 实验任务设计：高难度温度转换器

我们给智能体下发一个任务：
`“请编写一个 Node.js 函数 convertTemperature(val, scale)，支持摄氏度('C')与华氏度('F')的双向转换。”`

### 物理测试用例 (Evaluator 规则)：
为了测试大模型是否粗心，我们的单元测试裁判（Evaluator）设立了三个严苛的边界用例：
1.  **输入数字**：`convertTemperature(25, 'C')` 必须正确返回华氏度 `77.00`。
2.  **字符串容错**：输入字符串形式的数字 `convertTemperature("25", 'C')` 也必须自动转换返回 `77.00`。
3.  **非法输入拦截**：当输入非数字（如 `"abc"`）或未知单位时，**必须无条件抛出 `TypeError` 异常**。

普通大模型在第一轮接龙中，极易忽视第 2 点的类型转换和第 3 点的异常抛出，从而写出脆弱的 Bug 代码。

## 二、 动手实验：编写 Reflexion 闭环控制脚本

让我们在本地新建一个 `reflexion_demo.js` 脚本，完整实现三原色的闭环转译：

```javascript
const { OpenAI } = require("openai"); // 假设引入标准的 OpenAI SDK
const vm = require("node:vm");        // Node.js 内置虚拟机安全沙箱

const openai = new OpenAI({ apiKey: process.env.OPENAI_API_KEY });

// 模拟 Evaluator (单元测试裁判)
function evaluateCode(codeString) {
  try {
    // 1. 💡 物理安全隔离：使用 node:vm 虚拟机沙箱执行，剥夺访问 process 和 fs 的物理特权
    const sandbox = {};
    vm.createContext(sandbox);
    vm.runInContext(codeString, sandbox);
    const fn = sandbox.convertTemperature;

    if (typeof fn !== 'function') {
      return { success: false, error: "未在代码中找到名为 'convertTemperature' 的导出函数。" };
    }

    // 用例 1：数值转换
    const r1 = fn(25, 'C');
    if (r1 !== 77) throw new Error(`用例 1 失败：输入 25°C 期望返回 77，但得到了 ${r1}`);

    // 用例 2：字符串容错
    const r2 = fn("25", 'C');
    if (r2 !== 77) throw new Error(`用例 2 失败：输入字符串 "25" 期望自动兼容转为 77，但得到了 ${r2}`);

    // 用例 3：异常拦截
    try {
      fn("abc", 'C');
      throw new Error(`用例 3 失败：输入 "abc" 应该抛出 TypeError，但函数静默通过了。`);
    } catch (e) {
      if (!(e instanceof TypeError)) {
        throw new Error(`用例 3 失败：输入 "abc" 期望抛出 TypeError，但抛出了 ${e.name}: ${e.message}`);
      }
    }

    return { success: true };
  } catch (err) {
    return { success: false, error: err.message };
  }
}

// 主反射循环控制流
async function runReflexionLoop() {
  let reflectionMemory = []; // 反思记忆库
  let attempts = 0;
  const maxAttempts = 3;

  while (attempts < maxAttempts) {
    attempts++;
    console.log(`\n================ 第 ${attempts} 轮尝试 ================`);

    // 1. 组装带有反思记忆的 System Prompt
    let systemPrompt = "你是一个精确的 JavaScript 代码编写助手。请输出纯 JS 代码，不要带任何 Markdown 网页标签或解释。";
    if (reflectionMemory.length > 0) {
      systemPrompt += "\n\n⚠️ 历史失败反思经验（请在本次生成中严格遵守并纠正）：\n" + 
                      reflectionMemory.map((r, i) => `- [反思 ${i+1}]: ${r}`).join("\n");
    }

    // 2. 调用 Actor 生成方案
    const actorResponse = await openai.chat.completions.create({
      model: "gpt-4o-mini", // Actor 使用快速便宜的模型
      messages: [
        { role: "system", content: systemPrompt },
        { role: "user", content: "请编写 convertTemperature(val, scale) 函数。" }
      ]
    });
    
    const generatedCode = actorResponse.choices[0].message.content.replace(/```javascript|```/g, "").trim();
    console.log("🤖 [Actor 生成的代码草稿]:\n", generatedCode);

    // 3. Evaluator 动态跑测试用例
    const evalResult = evaluateCode(generatedCode);
    if (evalResult.success) {
      console.log("✅✅✅ [Evaluator 判定]: 测试用例 100% 通过！代码修复成功！");
      break;
    }

    console.log("❌ [Evaluator 判定]: 测试失败，报错信息为:", evalResult.error);

    // 4. 激活 Self-Reflection (高阶大脑自审)
    console.log("🧠 [Self-Reflection 启动]: 正在归因分析并生成反思记忆...");
    const reflectorResponse = await openai.chat.completions.create({
      model: "gpt-4o", // 反思器使用高阶极智模型
      messages: [
        {
          role: "system",
          content: "你是一个代码审计裁判。请对比用户写的 Bug 代码与测试用例报错，指出根本原因，并生成一句话的反思，教他下次怎么写。"
        },
        {
          role: "user",
          content: `【Bug 代码】:\n${generatedCode}\n\n【测试报错】:\n${evalResult.error}`
        }
      ]
    });

    const reflection = reflectorResponse.choices[0].message.content.trim();
    console.log(`💡 [提炼出的反思记忆]: "${reflection}"`);
    reflectionMemory.push(reflection); // 存入记忆库，等待下一轮注入
  }
}

runReflexionLoop();
```

## 三、 反射纠错日志跟踪输出分析

运行上面的脚本，你会在控制台清晰目睹智能体的大脑蜕变过程：
*   **第一轮**：Actor 忽略了边界，只写了简单的乘除公式，没有兼容字符串输入，也没有抛出 `TypeError`。测试用例 2 或 3 直接报错挂起。
*   **反思激活**：GPT-4o 裁判洞察到了“代码没有对 string 参数执行 parseFloat/Number 转化，且没有对非数抛出 TypeError”。生成反思记忆存入数组。
*   **第二轮**：Actor 的 System 头部被注入了刚才的反思。大模型注意力矩阵被“强制纠正偏置”。Actor 重新接龙，写出了高度安全的带有 `Number(val)` 与 `throw new TypeError` 校验的防弹代码，测试用例瞬间 100% 绿灯通过，完美闭环！

## 四、 【避坑指南】防范 eval 动态执行代码带来的 RCE 漏洞

在上面的 Evaluator 实现中，我们使用了一个极其致命的架构防线：**绝对禁止直接调用 Node.js 原生的 `eval(codeString)` 方法！**

### 1. RCE（远程代码执行）死穴
大模型生成的代码是不可控的。如果大模型在长对话中被用户恶意诱导，或者模型本身发生严重幻觉，生成了以下代码：
```javascript
const fs = require('fs');
fs.rmSync('/', { recursive: true }); // 物理删库！
```
如果 Evaluator 直接用 `eval()` 在当前进程内跑这段代码，整个宿主服务器会被瞬间“物理抹除”，密钥泄露。

### 2. 避坑策略：虚拟机 VM 沙箱隔离
正如我们在 `evaluateCode` 里的写法，**必须使用 Node.js 的核心 `node:vm` 模块**，创建一个与主线程隔离的、拥有完全空白 Context 的轻量级虚拟机：

```typescript
const vm = require('node:vm');
const sandbox = {}; // 创建一个完全不包含 process, require, fs 的空白沙箱上下文对象
vm.createContext(sandbox);

// 限制运行时间最大为 1000ms，防止死循环耗尽 CPU
vm.runInContext(generatedCode, sandbox, { timeout: 1000 });
```

通过这一层虚拟机隔离防御，生成代码即使包含恶意的删库和越权逻辑，也会因为在 sandbox 命名空间里找不到 `process` 或 `require` 而在第一步直接抛出 ReferenceError 异常被底座安全捕获，牢牢捍卫了服务器宿主的物理安全。

本节我们通过编写 Actor-Evaluator-Reflection 闭环完成了本地自纠错实验，并利用 `node:vm` 沙箱锁死了 RCE 越权漏洞。
