# 10.3 【白盒剖析】通道插件开发与消息转换

在 10.2 节中，我们建立了插件的静态元数据规范与零信任默认禁用的安全沙箱。当安全装配线就绪后，我们该如何真正开发一个通信适配通道插件，实现外部平台消息与底座事件总线的双向转换？

本节我们将实际白盒剖析 Freya 核心微信 iLink 通道插件（位于 `plugins/plugin-weixin-channel/src/index.ts`）的源码。

我们将一起拆解它是如何处理微信平台特有的多模态（图片、语音、文件）AES 加密文件解密，并将其翻译为 SDK 标准的 `connection:message` 与 `connection:reply` 双向事件桥接的。

---

## 一、 统一连接 ID (Connection ID) 的物理路由绑定

底座必须区分消息来自哪一个具体的微端、哪一个具体的群。微信插件将微信官方的机器人 ID `botId` 与微信聊天群/用户 ID `chatId` 拼接为唯一的全局连接标识：

```typescript
private getWeixinConnectionId(botId: string, chatId: string): string {
  return `weixin:${botId}:${chatId}`;
}
```

*   **物理优势**：这让 ConnectionManager 能够在一微秒内完成识别，并将其映射到对应的 `sessionId`，实现了跨平台的流量路由。

---

## 二、 微信多模态二进制数据的反向解密与转译

微信官方 iLink 服务器出于安全隐私考虑，向机器人推送的图片、视频和文件附件全部是通过**对称加密（AES）保护**的。

插件必须先在本地执行物理下载并反向解密，将其组装成 SDK 能够识别的 `FreyaAttachment` 标准附件：

```typescript
const items = weixinMsg.item_list || [];
for (const item of items) {
  let text = "";
  const attachments: FreyaAttachment[] = [];

  if (item.type === 1 && item.text_item?.text) {
    text = item.text_item.text; // 1. 文本消息
  } else if (item.type === 2) {
    // 2. 图片消息 (带 AES 加密)
    const imgUrl = item.image_item?.media?.full_url || "";
    const aesKey = item.image_item?.aeskey || "";
    let result;
    if (imgUrl) {
      // 💡 物理防线：调用内部解密器进行 AES 物理还原，并存入工作沙箱目录
      result = await this.downloadAndDecryptWeixinMedia(ctx, imgUrl, aesKey, "image.jpg", true);
    }
    if (result) {
      attachments.push({
        type: "image",
        mimeType: result.mimeType,
        path: result.path // 写入解密后的工作区物理相对路径
      });
    }
  } else if (item.type === 3) {
    // 3. 语音消息：读取微信官方接口自动语音识别转译的文字内容
    const voiceText = item.voice_item?.text || "";
    text = `[语音转文字: ${voiceText || "未识别"}]`;
  } else if (item.type === 4 && item.file_item) {
    // 4. 文件附件 (带 AES 加密)
    const fileUrl = item.file_item.media?.full_url || "";
    const fileName = item.file_item.file_name || "未命名文件";
    const aesKey = item.file_item.media?.aes_key || "";
    let result = await this.downloadAndDecryptWeixinMedia(ctx, fileUrl, aesKey, fileName, false);
    if (result) {
      attachments.push({ type: "file", mimeType: result.mimeType, path: result.path });
    }
  }
}
```

经过这一层转译，微信平台复杂的 AES 乱序二进制，被净化为了标准的结构化纯文本与解密文件实体，为接下来的“事件上报”打好了物理基础。

## 三、 双向事件桥接的物理闭环

微信插件在 `setup(ctx)` 期间，拉起与底座核心 EventBus 的桥接。整个通信闭环通过两个方向的异步事件实现解耦：

```
 微信官方 API (外部)
      │
      ▼ (长轮询 getUpdates 捕获消息)
 [微信通道插件] ── 1. emit("connection:message") ──> [底座 EventBus] ──> (核心 ReAct 推理)
      │                                                                  │
      ▲ ── 2. on("connection:reply")  <── [底座 EventBus] <──────────────┘
      │
      ▼ (调用 sendWeixinMessage 推送)
 微信用户屏幕 (用户可见)
```

### 1. 输入事件上报（微信 -> 底座内核）
当微信插件接收到解密后的文本及附件后，向总线上报 `connection:message` 唤醒底座：

```typescript
if (text || attachments.length > 0) {
  // 1. 广播连接已激活，告知 ConnectionManager 该通道当前在线
  ctx.eventBus.emit("connection:active", {
    connectionId,
    defaultSessionId: connectionId,
    staleThresholdMs: 0
  });

  // 2. 将消息与文件上载总线
  ctx.eventBus.emit("connection:message", {
    connectionId,
    content: text,
    attachments
  });
}
```

### 2. 输出事件接管与回传（底座内核 -> 微信）
插件在 `setup()` 钩子中，订阅 `connection:reply` 答复事件。一旦监听到属于本通道的回复，立刻反向推回微信：

```typescript
async setup(ctx: FreyaContext): Promise<void> {
  this.context = ctx;

  // 💡 订阅统一消息回复事件
  ctx.eventBus.on("connection:reply", async (payload: { connectionId: string; content: string }) => {
    const prefix = "weixin:";
    // 过滤是否是发往微信通道的消息
    if (payload.connectionId.startsWith(prefix)) {
      // 提取 connectionId 中的 botId 和 chatId
      const parts = payload.connectionId.slice(prefix.length).split(":");
      if (parts.length >= 2) {
        const botId = parts[0];
        const chatId = parts.slice(1).join(":");
        // 🚀 物理回传：将大模型的最终文本发送回微信官方接口
        await this.sendWeixinMessage(botId, chatId, payload.content);
      }
    }
  });
}
```

### 物理设计的解耦美学：
在这套闭环下，微信插件的代码中**找不到任何对 `AgentExecutor` 或 `SessionManager` 的物理强引用**。它只跟 SDK 中的 EventBus 发生通信。

内核对微信平台的 API 变化也完全不需要有任何代码层面的感知。双向事件管道在内存中完成了最优雅的抽象对齐。
