# 9.3 【白盒剖析】中断流转与抢救性结算

在 9.1 和 9.2 节中，我们建立了基于 AbortSignal 的物理控制网络以及 EventBus 多通道解耦通信。本节我们将实际切入 Freya 内核的核心服务（位于 `packages/core/src/agent/agent-service.ts`）源码。

我们将白盒剖析底座是如何在捕获到 `AbortError` 中断异常时，进行**半截响应文本（Partial Response）的抢救性落盘**，以及如何在父子智能体之间实现**异步级联刹车控制**的。

---

## 一、 中断生命周期控制链

当用户发起对话时，`AgentService` 会在 `executeChat` 或 `handleRequest` 阶段，为当前 `sessionId` 实例化专属的 `AbortController` 并挂载到本地字典：

```typescript
const controller = new AbortController();
this.abortControllers.set(message.sessionId, controller); // 注册控制器

const response = await this.agentExecutor.run(
  message.sessionId,
  {
    signal: controller.signal, // 透传刹车信号
    onChunk: (deltaText) => {
      partialResponse += deltaText; // 实时累加已经生成的流式文本
      this.context.eventBus.emit('session:reply:delta', { sessionId: message.sessionId, text: deltaText });
    }
  },
);

this.abortControllers.delete(message.sessionId); // 正常结束，移除控制器
```

在流式吐字期间，`partialResponse` 字符串像一个漏斗，实时收纳大模型吐出的每一个 Token。这为接下来的“抢救性落盘”做好了物理准备。

---

## 二、 中断异常捕获与“部分响应”抢救性落盘 (Partial Response Saving)

当用户点击停止按钮，信号拉起，大模型网络 fetch 请求被截断，`agentExecutor.run()` 会因为网络链路强行重置而抛出 `AbortError` 异常，被外层的 `catch` 块拦截。

### 1. 新手最容易犯的“记忆丢失与计费糊涂账”大坑
*   **痛点**：很多初学者在写 `catch(err)` 时，一旦发现是用户主动取消了，就直接什么都不做（甚至直接清空历史）。
*   **后果**：
    1.  大模型虽然只说了一半，但这几百个 Token 已经在云端真实消费并计费了。如果不把这一半文本存入历史，账单上的 Token 消耗将对不上，形成糊涂账。
    2.  大模型脑子里的对话历史出现了“断层”。大模型不知道自己刚才说了什么。下一轮用户接着问时，大模型会因为缺乏半截语境产生答非所问。

### 2. Freya 的解决方案：*(interrupted)* 钢印落盘
在 `agent-service.ts` 的 catch 块中，内核引入了极其巧妙的**部分响应抢救性落盘**：

```typescript
try {
  const response = await this.agentExecutor.run(...);
} catch (err: any) {
  // 1. 拦截 AbortError (包括用户手动中止或网络超时)
  if (err.name === 'AbortError') {
    this.context.logger.warn(`Session ${message.sessionId} generation aborted by user.`);

    // 2. 💡 抢救性检查：如果此前大模型已经流式吐出了一半文本
    if (partialResponse.trim()) {
      // 强行将这半截子文本作为 role: "assistant" 追加存入 Session 数据库
      // 并在末尾刻上 `*(interrupted)*` 的物理钢印，通知 LLM 此处被强行切断了
      await this.sessionManager.appendMessage(message.sessionId, {
        role: 'assistant',
        content: `${partialResponse}\n\n*(interrupted)*`
      });
    }
  } else {
    // 处理其他真正内核报错
    ...
  }
} finally {
  // 3. 清理控制器缓存，并将持久化会话刷盘，向外广播完成事件平稳关闭流通道
  this.abortControllers.delete(message.sessionId);
  await this.sessionManager.flushSession(message.sessionId);
  this.context.eventBus.emit('session:reply:completed', { sessionId: message.sessionId });
}
```

*   **物理设计优势**：
    这不仅让已发生的计费 Token 得到了物理归档（账单与历史完美一致），更为大模型在下一轮决策中提供了极其精准的心流断点——当大模型在下一轮看到以 `*(interrupted)*` 结尾的历史消息，它的自注意力层瞬间就能理解“刚才我的话被主系统掐断了”，从而优雅地在下一句中做补偿性回答，体验极其顺滑。

## 三、 父子智能体的异步级联刹车

在 Freya 的 Monorepo 微内核设计中，支持一个父智能体（如 Host Agent）拉起多个子智能体（Sub Agent）进行并发计算。

当父会话接收到中断请求时，底座不仅要中止主会话的生成流，更必须**级联终止**其派生的所有后台子智能体，保障级联生命周期的平稳注销。

### 1. 复合键注册与 Signal 透传
在 `AgentService.delegateTask` 派发子任务时，通过 `${parentSessionId}_sub_${childSessionId}` 复合键将子控制器的生命周期纳管于统一字典中，并将信号透传给子智能体的执行链路：

```typescript
async delegateTask(parentSessionId: string, childSessionId: string, prompt: string, options?: ...): Promise<string> {
  const ctrl = new AbortController();
  const key = `${parentSessionId}_sub_${childSessionId}`;
  this.abortControllers.set(key, ctrl);

  try {
    ...
    // 透传子控制器的 signal
    const replyMessage = await this.agentExecutor.run(childSessionId, {
      signal: ctrl.signal,
      providerId: options?.providerId,
      modelId: options?.modelId
    });
    return replyMessage.content;
  } finally {
    this.abortControllers.delete(key);
    await this.sessionManager.flushSession(childSessionId);
  }
}
```

### 2. EventBus 事件驱动的前缀级联中断
当用户下发中断命令（如 CLI 输入 `/stop` 或前端点击中止按钮）时，系统会向 EventBus 发射 `session:interrupt` 事件。`AgentService` 通过监听该事件自动完成父会话与派生子会话的全局刹车：

```typescript
this.context.eventBus.on('session:interrupt', (payload: { sessionId: string }) => {
  this.messageQueues.delete(payload.sessionId);

  // 1. 中止主会话生成流
  const controller = this.abortControllers.get(payload.sessionId);
  if (controller) {
    controller.abort();
    this.context.logger.warn(`[AgentService] Interrupted generation stream for session ${payload.sessionId}.`);
    this.abortControllers.delete(payload.sessionId);
  }

  // 2. 遍历控制器字典，级联中止所有派生的子智能体会话
  for (const [key, childCtrl] of this.abortControllers.entries()) {
    if (key.startsWith(`${payload.sessionId}_sub_`)) {
      childCtrl.abort();
      this.abortControllers.delete(key);
      const subSessionId = key.substring(`${payload.sessionId}_sub_`.length);
      // 将子会话状态标记为 failed，防止无限挂起
      this.sessionManager.updateSession(subSessionId, { status: 'failed', durationMs: 0 }).catch(() => { });
      this.context.logger.warn(`[AgentService] Cascadely interrupted subagent session ${subSessionId}.`);
    }
  }
});
```

通过这套基于 EventBus 的前缀级联中断架构，主会话的中断信号能够在事件驱动下自动下发并斩断所有后台空转的子代计算资源，无需依赖人工显式工具调用，彻底消除了后台僵尸堆栈。
